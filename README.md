# Трекинг объекта на видео

Лабораторная работа № 2. Программа отслеживает плоский прямоугольный объект
и рисует вокруг него рамку с подписью. Написана на Python с OpenCV и NumPy.

## Запуск

Нужен Python 3.10 или новее. В PowerShell из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запуск на собственном видео:

```powershell
.\.venv\Scripts\python.exe main.py --input data/videos/test_cv.mp4 --output results/videos/test_cv_tracked.mp4 --label Cover
```

На первом кадре нажмите мышью на **четыре угла объекта по контуру**, затем **Enter**.
Клавиша **R** сбрасывает выбор, **Q** или **Esc** завершает работу.
Для другого ролика замените путь после `--input` и имя результата после `--output`.

Программа сохраняет обработанное видео, статистику по кадрам в CSV и сводку в JSON.
Готовый результат собственной съёмки можно [открыть здесь](results/videos/playback/test_cv_tracked.mp4).

Если новое видео не открывается в VS Code, подготовьте совместимую MP4-копию:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-preview.txt
.\.venv\Scripts\python.exe prepare_previews.py
```

Она появится в `results/videos/playback/`.

## 1. Теоретическая база

**Ключевые точки** — заметные детали изображения, которые можно найти на разных кадрах.
**Дескрипторы** описывают окрестности этих точек и позволяют сопоставлять их между собой.
В проекте используются ORB и BFMatcher. Неоднозначные совпадения отбрасываются через ratio test.

По найденным соответствиям вычисляется **гомография** — преобразование плоскости,
учитывающее поворот, масштаб и перспективу. **RANSAC** отсеивает ошибочные соответствия.
Если совпадений ORB недостаточно, **оптический поток Lucas–Kanade** переносит точки
с предыдущего кадра на текущий.

## 2. Описание системы

Алгоритм работает так:

1. Пользователь выделяет объект на первом кадре. Он становится эталоном.
2. ORB находит ключевые точки внутри выделенной области и на следующих кадрах.
3. По совпадениям с эталоном вычисляются новые координаты четырёх углов объекта.
4. Если поиск по ORB не удался, программа пробует сопровождение оптическим потоком.
5. При успешном поиске рисуется рамка. При потере показывается `LOST`, поиск продолжается.

Зелёная рамка означает поиск по ORB, голубая — сопровождение оптическим потоком (`FLOW`).
Синие точки показывают найденные признаки, жёлтые — совпадения, зелёные — точки,
прошедшие проверку RANSAC.

### Тестовые видео

В роликах меняются масштаб, поворот и перспектива объекта. Проверка выполнена 21.10.2026.
Оптический поток помогает удерживать рамку при уменьшении объекта, но потери остаются.
В обычном ролике рамка отсутствует на кадрах 303–389 и восстанавливается на кадре 390.
Эталоном выбрана видимая область репродукции на первом кадре, а не внешний край листа.

Это три варианта **одной съёмки**, поэтому сцена и движение камеры совпадают.
Покадровое сравнение исходных AVI показало: обычный ролик и `mona-lisa-blur.avi`
отличаются только на кадрах **10–35** (примерно 0,33–1,17 с, нумерация с нуля).
Остальные 532 кадра совпадают полностью. Версия `extra-credit` отличается
на всех 558 кадрах, но также показывает ту же сцену; название не означает,
что размытие сильнее на всём протяжении видео.

## 4. Выводы

Программа отслеживает объект при изменении положения, масштаба и перспективы.
На собственной съёмке потерь нет. На тестовых видео оптический поток улучшает
сопровождение, однако полностью устранить потери не удалось.

Лучше всего подходят объекты с чётким рисунком. Сильное размытие, блики,
перекрытия и маленький размер объекта затрудняют поиск. При сопровождении
оптическим потоком возможны дрожание и постепенное смещение рамки.
