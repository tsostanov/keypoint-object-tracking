# Лабораторная работа № 2
# Трекинг объекта на видео на основе ключевых точек

**Цель:** находить плоский прямоугольный объект на последовательных кадрах видео
и показывать его границы с учётом поворота, масштаба и перспективы.
Реализация: Python, OpenCV и NumPy; ORB → BFMatcher → ratio test → RANSAC → гомография.

Программа реализована и проверена на синтетическом видео. Три ролика преподавателя
и самостоятельно снятое видео пока не предоставлены: испытания на них предстоят.

## Установка и запуск

Требуется Python 3.10 или новее. Проверенная среда: Windows 11, Python 3.13.7,
OpenCV 4.14.0, NumPy 2.5.4. Для выбора мышью нужна графическая сессия и пакет
`opencv-python`, не `opencv-python-headless`.

Windows PowerShell, из корня репозитория (активировать окружение необязательно):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe demo.py --directory results/demo_local
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Для точного повторения проверенного набора зависимостей можно установить
`numpy==2.5.4 opencv-python==4.14.0.94` вместо диапазонов из requirements.txt
в среде Python 3.13. Время обработки зависит от компьютера и версий библиотек.

В Linux/macOS команды окружения: `python3 -m venv .venv`,
`.venv/bin/python -m pip install -r requirements.txt`, далее `.venv/bin/python main.py …`.

Положите реальные видео в `data/` по [инструкции](data/README.md). Первый запуск:

```powershell
.\.venv\Scripts\python.exe main.py --input data/test_1.mp4 --output results/test_1_tracked.mp4 --label Book
```

Если окружение активировано, достаточно:

```powershell
python main.py --input data/test_1.mp4 --output results/test_1_tracked.mp4
```

Выбор объекта:

1. Нажмите левой кнопкой мыши на четыре угла **по контуру** — по часовой стрелке
   или против неё. Начать можно с любого угла; нельзя пересекать стороны.
2. Нажмите **Enter** для подтверждения. Неверная геометрия не принимается.
3. **R** сбрасывает точки; **Q**, **Esc** или закрытие окна отменяют выбор.
4. При просмотре результата **Q**, **Esc** или закрытие окна завершают обработку,
   сохраняя уже обработанную часть и её статистику.

На больших кадрах окно выбора уменьшено до 1280×800; точки сохраняются
в исходных координатах. При указанном имени результата углы автоматически
записываются в `results/test_1_selection.json`. Повторный запуск без окон:

```powershell
python main.py --input data/test_1.mp4 --output results/test_1_tracked.mp4 --selection results/test_1_selection.json --no-preview
```

JSON содержит `frame_size: [ширина, высота]` и `corners: [[x, y], …]` — четыре пары
чисел в порядке обхода. Он подходит к тому же первому кадру; совпадение размера
само по себе не гарантирует, что выбрано то же видео. `--no-preview` требует
`--selection`. Подпись `--label` — печатные ASCII-символы, например `Book`.

Выход: MP4 (`mp4v`) или AVI (`MJPG`), CSV и JSON рядом с видео. Каталоги создаются
автоматически. Сохраняются размеры и FPS; при отсутствующем, бесконечном,
неположительном FPS или значении выше 1000 применяется **25 FPS** с предупреждением.
Нечётные размеры отклоняются с объяснением, поскольку видеокодек может молча
обрезать край. Звуковая дорожка не переносится. Временные метки CSV вычисляются
как номер кадра / FPS; видео с переменной частотой преобразуется в постоянную.
Повторный запуск с тем же выходным именем заменяет результаты. Совпадение входных
путей с выходным видео или файлами статистики запрещено, включая ссылки на тот же файл.

Ошибки входных файлов, JSON, кодека и параметров выводятся без traceback с кодом
завершения 1. Отмена выбора — код 0, Ctrl+C — 130. При Ctrl+C или ошибке посередине
могут остаться частичные видео/CSV; итоговая сводка текущего запуска не создаётся.
Не используйте оставшийся от предыдущего запуска JSON для оценки такого результата.

## 1. Теоретическая база

**Ключевая точка** — локальная деталь изображения, которую можно повторно найти
на другом кадре. **Дескриптор** кодирует окрестность этой точки для сопоставления.
Текстурированная обложка подходит лучше однотонного прямоугольника.

**ORB** использует детектор FAST, отбор точек по отклику углов и пирамиду масштабов.
Ориентация окрестности учитывается при построении бинарного дескриптора на основе
BRIEF. Это помогает при вращении и умеренном изменении масштаба.
[Документация ORB](https://docs.opencv.org/4.x/d1/d89/tutorial_py_orb.html).

**BFMatcher** сравнивает дескрипторы. Для стандартного ORB применяется расстояние
Хэмминга — количество различающихся битов. KNN находит два ближайших варианта.
**Ratio test** оставляет лучший, если `d1 < ratio * d2`: слишком похожие кандидаты
считаются неоднозначными. Дополнительно в программе одна точка текущего кадра
используется только один раз.
[Сопоставление признаков](https://docs.opencv.org/4.x/dc/dc3/tutorial_py_matcher.html).

**Гомография** — матрица 3×3, определённая с точностью до масштаба:

```text
s · [x', y', 1]ᵀ = H · [x, y, 1]ᵀ
```

Она описывает проективное преобразование плоскости между изображениями.
Поэтому подходит для плоской обложки при движении камеры или объекта,
если искажения объектива невелики. Неплоский объект одной гомографией в общем
случае описать нельзя. Четыре соответствия в невырожденном расположении дают
математический минимум, но для устойчивости здесь используются более строгие пороги.

**RANSAC** оценивает преобразования по небольшим выборкам и ищет согласованный
набор соответствий. **Inlier** — пара точек, ошибка репроекции которой укладывается
в заданный порог. Четыре исходных угла преобразуются найденной матрицей;
получается перспективный четырёхугольник.
[Пример гомографии и RANSAC](https://docs.opencv.org/4.x/d1/de0/tutorial_py_feature_homography.html).

## 2. Описание разработанной системы

| Файл / функция | Назначение |
| --- | --- |
| `main.py: build_parser` | Аргументы запуска и настройки |
| `main.py: process_video` | Чтение первого кадра, основной цикл, запись, CSV/JSON, освобождение ресурсов |
| `selection.py: choose_corners` | Выбор четырёх углов мышью и подтверждение |
| `selection.py: save_selection / load_selection` | JSON, проверка размера и геометрии |
| `tracker.py: KeypointTracker.__init__` | ORB по маске выбранного объекта первого кадра |
| `tracker.py: KeypointTracker.detect` | ORB текущего кадра, KNN, ratio test, уникальные пары, RANSAC |
| `tracker.py: valid_quad` | Проверка конечности, выпуклости, площади и пересечения с кадром |
| `tracker.py: draw_detection` | Рамка, подпись, статус, число inlier |
| `demo.py` | Генерация ролика с известной геометрией и проверка результата |
| `tests/test_tracking.py` | Автоматические проверки алгоритма, ввода и записи видео |

Точки эталона выбираются маской четырёхугольника, поэтому фон вне объекта
не используется для выбора опорных точек. Координаты точек и углов относятся
к полному первому кадру, обрезки изображения нет.

Текущий кадр всегда сопоставляется с неизменным эталоном. Накопления преобразований
между соседними кадрами нет. При недостатке дескрипторов, совпадений, inlier или
при неверной геометрии выдаётся **LOST**, рамка отсутствует. Следующий кадр снова
проверяется целиком, поэтому после возвращения объект может обнаружиться повторно.

Дополнительно исключаются гомографии с проективным горизонтом внутри объекта.
Частичный выход за изображение разрешён, если рамка ещё пересекает кадр.
Слишком удалённые координаты ограничиваются десятикратным размером кадра
для защиты от численной нестабильности. Проверки снижают риск ложных рамок,
но не доказывают правильность обнаружения.

### Настройки

Все параметры доступны как аргументы, полный список: `python main.py --help`.

| Аргумент | По умолчанию | Значение |
| --- | ---: | --- |
| `--nfeatures` | 2500 | Максимум признаков ORB |
| `--scale-factor` | 1.2 | Шаг масштаба пирамиды |
| `--nlevels` | 8 | Число уровней пирамиды |
| `--fast-threshold` | 15 | Порог детектора FAST |
| `--ratio` | 0.75 | Фильтрация неоднозначных совпадений |
| `--min-matches` | 12 | Минимум пар для попытки RANSAC |
| `--min-inliers` | 10 | Минимум согласованных пар |
| `--min-inlier-ratio` | 0.45 | Минимальная доля согласованных пар |
| `--ransac-threshold` | 3.0 | Допустимая ошибка репроекции, пиксели |
| `--min-area-ratio` | 0.001 | Минимум площади рамки / площади кадра |
| `--max-area-ratio` | 1.5 | Максимум площади рамки / площади кадра |

Это стартовые значения. Большее число признаков увеличивает время сопоставления.
Повышение ratio допускает больше пар, включая ошибочные. Порог RANSAC выражен
в пикселях и зависит от разрешения. Настройки следует подбирать по визуальной
проверке конкретного видео, сохраняя параметры вместе с результатами.

### Статистика

CSV: `frame` (с нуля), `video_time_s`, `status`, `matches`, `inliers`,
`inlier_ratio`, `processing_ms`, `reason`. Причина LOST позволяет отличить
недостаток признаков, недостаток совпадений и отбраковку геометрии.

Кадр 0 записывается в видео и CSV как **REFERENCE**. Он задан пользователем
и исключён из `processed_frames`, `detected_frames`, доли обнаружений и среднего времени.
`written_frames` включает эталон. Видео из одного кадра имеет нулевые метрики поиска.

JSON содержит числа обработанных и найденных кадров, `detection_rate`,
`mean_processing_ms`, `processing_fps`, `pipeline_fps`, FPS/размер видео,
параметры трекера и признак остановки пользователем. Время обработки кадра включает
поиск и отрисовку, но исключает декодирование, запись и ожидание GUI.
`processing_fps = 1000 / mean_processing_ms`. `pipeline_fps` учитывает цикл ввода/вывода
и просмотр, исключая выбор эталона; это отдельный ориентир производительности.

**Доля обнаруженных кадров не является точностью.** Без истинных границ неизвестно,
правильна ли каждая рамка. Кроме того, LOST на кадре без объекта — корректное поведение,
хотя доля TRACKING снижается. Для оценки локализации нужна ручная разметка углов
или масок; для демонстрации ниже истинные углы известны из генератора.

## 4. Выводы по работе

Реализован поиск объекта по признакам эталона с перспективной рамкой и
восстановлением после потери. Синтетические испытания подтвердили согласованность
координат, запись видео и статистики, а также отбраковку кадров без объекта.
Проверка на обязательных четырёх реальных видео остаётся необходимым этапом сдачи.

ORB требует различимых деталей. Размытие, блики, однотонная поверхность и сильное
уменьшение объекта сокращают число устойчивых признаков. Перекрытия и сильное
изменение ракурса могут оставить слишком мало совпадений. Повторяющийся рисунок
создаёт неоднозначные пары; RANSAC и фильтры уменьшают, но не исключают ложные рамки.
Гомография не учитывает изгиб объекта и значительную дисторсию объектива.
Межкадровое сглаживание не применяется: возможное дрожание рамки отражает
независимые оценки каждого кадра. При недостаточной уверенности программа
показывает LOST и продолжает поиск.
